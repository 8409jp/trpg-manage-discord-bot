# TRPG Manage Discord bot (TRPG セッション管理 Bot)

TRPG のセッション環境作成、ダイスロール、セルフロール管理、およびセッション終了後のログアーカイブ・整理を自動化する Discord Bot です。
複数サーバーでの利用に対応しており、サーバーごとの設定をローカルファイルで安全に管理します。

---

## 主な機能

- 🎲 **セッション環境の自動構築 (`/session-create`)**
  - セッション専用ロール、プライベートカテゴリ、基本テキストチャンネル、GM/観戦用チャンネルを自動生成
  - 通話用プライベートボイスチャンネル（`SESSION - Main` / `SESSION - Sub`）を同時作成
- 📁 **ワンクリック・ログアーカイブ (`/session-archive`)**
  - チャンネルの会話ログを Discord 風 HTML 形式で抽出し、zip 形式にまとめてアーカイブ保存
  - 画像や添付ファイルを含む完全保存に対応（25MB を超える場合は自動で軽量な「ライトモード」にフォールバック）
  - セッション参加者へアーカイブ閲覧権限を自動付与
- 🗑️ **環境クリーンアップ (`/session-delete`)**
  - アーカイブせずにセッション環境（カテゴリ・全チャンネル・ボイスチャンネル・ロール）を一括削除
- 🎭 **セルフロールパネル設置 (`/role-self`)**
  - ユーザーが自分自身でロールを着脱できるボタン（取得/解除）をチャンネルに設置
- 🎲 **ダイスボット機能 (BCDice 連携)**
  - チャット欄でダイスコマンド（例: `1d100<=50`, `2d6+3`, `CC<=70` など）を入力するだけでダイス結果を返信
  - Bot へのメンション付き（例: `@Bot 1d100`）でも正常に認識

## 1. 準備

1. [Discord Developer Portal](https://discord.com/developers/applications) でアプリケーションを作成し、Bot トークンを取得してください。
2. Bot の **Privileged Gateway Intents** で以下を有効にしてください。
   - `Guild Members` (ロールメンバーの取得に必要)
   - `Message Content` (ダイスコマンドの監視に必要)
3. Bot をサーバーに招待する際、以下の権限を付与してください。
   - `Administrator` (チャンネル・ロール・権限の管理に必要なため)

---

## 2. 環境構築

### 必要な環境
- Node.js (v18以上推奨)
- npm

### 手順
1. リポジトリをクローンします。
2. プロジェクトのルートディレクトリで `.env` ファイルを作成し、以下を記入します。
   ```ini
   DISCORD_TOKEN=あなたのBotトークン
   CLIENT_ID=あなたのBotのアプリケーションID
   ```
3. 依存関係をインストールします。
   ```bash
   npm install
   ```

---

## 3. 起動方法

1. **スラッシュコマンドの登録**（初回およびコマンド定義の変更時）
   ```bash
   node src/deploy-commands.js
   ```
   ※ グローバル登録のため、Discord 全体に反映されるまで数分〜最大1時間程度かかる場合があります。

2. **Bot の起動**
   ```bash
   node src/index.js
   ```

## 4. コマンド一覧と使い方

### 管理・セッション運用コマンド

#### 1. アーカイブ先の設定
- **`/setup-archive`**
  - サーバーごとのセッションログ保存先カテゴリを設定します。
  - **オプション:**
    - `category_id` (必須): アーカイブ先とするカテゴリの ID。
  - ※ 設定は `./data/config.json` にサーバー単位で保存されます。

#### 2. セッション環境の作成
- **`/session-create`**
  - セッション用のロール、カテゴリ、チャンネルをまとめて自動作成します。
  - **オプション:**
    - `name` (必須): セッション名（ロール名やカテゴリ名に使用されます）。
    - `use_gm` (任意): GM専用ロールと「GM用」チャンネルを作成するか（デフォルト: `false`）。
    - `use_observer` (任意): 観戦用ロールと「観戦」チャンネルを作成するか（デフォルト: `false`）。
  - **自動作成されるチャンネル・環境:**
    - **カテゴリ**: セッション名（ロール付与者のみ閲覧可能なプライベート設定）
    - **テキストチャンネル**:
      - `連絡`, `雑談`: 参加者・GM・観戦が閲覧・書き込み可能
      - `CS提出所`: 観戦者は閲覧のみ（書き込み制限）
      - `GM用`（`use_gm: true` 時）: GMのみ閲覧・書き込み可能
      - `観戦`（`use_observer: true` または `use_gm: true` 時）: GMおよび観戦者のみ書き込み可能
    - **ボイスチャンネル**:
      - `SESSION - Main`, `SESSION - Sub`: ロール所持者のみ接続・閲覧可能なプライベート通話チャンネル

#### 3. セッションのアーカイブ
- **`/session-archive`**
  - セッションを終了し、テキストチャンネルのログを HTML + 添付ファイル付き zip にまとめて保存します。
  - **オプション:**
    - `category` (必須): アーカイブ対象のカテゴリ名（**入力候補から選択可能**。カテゴリIDの直接入力にも対応）。
    - `delete_roles` (任意): セッション終了後に関連ロールを削除するか（デフォルト: `false`）。
    - `delete_channels` (任意): 完了後にセッションカテゴリ配下のチャンネル（ボイスチャンネル含む）とカテゴリを削除するか（デフォルト: `false`）。
    - `target_channel_id` (任意): zip を特定の既存チャンネルに送信したい場合に指定。未指定の場合は `/setup-archive` で指定したアーカイブカテゴリ内に新チャンネルを作成します。
  - **仕様詳細:**
    - zip アーカイブにはテキストチャンネルの履歴が含まれ、通話用のボイスチャンネルは自動的に除外されます。
    - アーカイブ完了後、セッション参加者（PL・GM・観戦）へ新アーカイブチャンネルの閲覧権限が自動付与されます。
    - zip ファイルサイズが Discord のアップロード上限（25MB）を超える場合、自動的に画像アセットを除外した「ライトモード」で再生成・送信されます。

#### 4. セッション環境の直接削除
- **`/session-delete`**
  - アーカイブを残さずに、セッション環境（カテゴリ、配下のテキスト・ボイス全チャンネル、関連ロール）を一括削除します。
  - **オプション:**
    - `category` (必須): 削除対象のカテゴリ名（**入力候補から選択可能**。カテゴリIDの直接入力にも対応）。
    - `confirm` (必須): 誤操作防止のため、`True` を選択する必要があります。

#### 5. セルフロールパネルの設置
- **`/role-self`**
  - ユーザーがボタンを押して自分でロールを取得・解除できるパネルをチャンネルに設置します。
  - **オプション:**
    - `role` (必須): 対象とするロール。
    - `label` (任意): パネルに表示するラベル（省略時はロール名）。
  - **特徴:**
    - 「取得（緑色/➕）」ボタンと「解除（赤色/➖）」ボタンが分離されており、直感的に操作可能。
    - 既に持っている場合の取得や、持っていない場合の解除時には親切な案内メッセージ（自分にしか見えない Ephemeral 通知）が表示されます。

---

### チャット・ダイスボット機能 (BCDice)

Bot が参加しているチャンネルでダイスコマンドを入力すると、BCDice エンジンが判定を行い結果を返信します。

- **基本的なダイス:**
  - `1d100` / `2d6+3` / `4dF` など
- **TRPG 特有の判定コマンド:**
  - `CC<=50` / `1D100<=70`（技能ロール、クリティカル・ファンブル判定）
  - 各種シークレットダイスや計算式
- **Bot メンションへの対応:**
  - `@Bot 1d100` や `@Bot CC<=60` のように Bot へメンションを飛ばして入力した場合でも、メンション部分を自動で取り除いてダイスを振ります。

## 5. pm2 による常駐起動（Windows 11 / Linux）

Bot をバックグラウンドの常駐プロセスとして管理したい場合、[pm2](https://pm2.keymetrics.io/) の利用を推奨します。

### インストール

```bash
npm install -g pm2
# Windows 環境で自動起動を設定する場合:
npm install -g pm2-windows-startup
```

### 起動とプロセス管理

```bash
# Bot を起動して常駐化
pm2 start src/index.js --name trpg-bot

# 状態確認・ログ確認
pm2 list
pm2 logs trpg-bot

# 再起動・停止
pm2 restart trpg-bot
pm2 stop trpg-bot
```

### OS 起動時の自動起動設定（Windows）

```powershell
pm2 save
pm2-startup install
```
> **注意:** `pm2-startup install` は管理者権限の PowerShell で実行してください。

## 6. 補足・仕様メモ

- **設定データ:**
  - 各サーバーのアーカイブ先カテゴリ設定は `./data/config.json` に保存されます。
- **キャッシュ対策:**
  - Bot 再起動直後など Discord の内部キャッシュが空の状態でもメンバーやチャンネルの取得漏れが起きないよう、各種コマンド実行時に事前フェッチ処理を行っています。
- **セッション用ボイスチャンネル:**
  - `/session-create` で作成される「SESSION - Main」「SESSION - Sub」は、作成されたセッション用ロール所持者のみが入室できるプライベート設定になっています。
